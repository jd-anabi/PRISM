## 13. Tests, the stages of the build, the pages and the walkthrough

> **Read with section 8 of the design's main file** ("Deviations recorded while planning and building"): where a row there departs from this part, the row wins.

How the design is built and proven (U19): the fate of each of today's tests, the fixtures and the new suites, the gate each task passes, the nine stages, what every reader page must say afterwards, and the rows the owner runs on a real screen. It changes nothing a screen shows. Code is cited as at `c45cc4a`; no file under `core/` or `tests/` has changed since.

### 13.1 The tests

#### 13.1.1 What holds the window today

Nine suites, 322 test functions (`grep -c '^def test_'`): `tests/test_nav_and_gating.py` 101, `test_worker_dispatch.py` 41, `test_artifact_browser.py` 39, `test_settings_persistence.py` 31, `test_vt_progress.py` 23, `test_simulate.py` 17, `test_figures.py` 19, `test_user_models.py` 46, `test_docs.py` 5.

They hold the window four ways: by attribute name on widgets built off-screen with no arguments (`InferenceScreen()` is written 47 times in `tests/*.py`, `MainWindow()` 20 times, `FdtPanel()` or `CrossValPanel()` 44 times, on 37 lines); by wording; by the dialog mechanism (the session guard replaces `QMessageBox.exec`, `tests/conftest.py:185-188`, and a scan forbids the static calls, `tests/test_refusals.py:918`); and by source text through `code_only` (`tests/_fixtures.py:101-112`). The design keeps none of the four as a group, so each of the 322 gets an explicit fate.

#### 13.1.2 The rule, and the carried-over list

- **A behaviour pin** (what a click does, what is refused, what is written, what is never remembered, how a stop and a close behave, what a figure survives) is carried over whatever the layout: its assertions stay, only the way the test reaches the widget changes (13.1.4), and it is never deleted. Where a decision reverses the behaviour, the pin is inverted in the task that makes the change and Table B names the decision.
- **A wording pin or a structure pin** is rewritten to the new words or structure BEFORE the code it covers, in the same task, and is seen to fail for the right reason first.
- **A source-text pin** stays only where it is a scan that does not depend on layout (no static dialog call, no literal `Resources/` path, no cited working document). A pin on the source of a screen's builder is retired in favour of the read-back of the built page, which is behaviour.

**The carried-over list** (a choice the owner has not seen): one row per today's test, 322 rows, each with its fate: kept; re-pointed; rewritten (to what); inverted (which decision); replaced (by which test); retired (why). It is a text table in the plan's gitignored workspace under `.superpowers/sdd/`. Each stage's exit compares `pytest --collect-only -q` with it: a test that is gone without a row fails the stage.

#### 13.1.6 The gate for every task

1. The task's tests are written or rewritten first and run alone (one file, one process) to fail for the stated reason. The code is written; the same file runs green; the task is committed.
2. The review starts, and with it ONE fast gate, `pytest -m "not slow"`, one process, in the background, logging to the task's workspace. Until it exits no file under `core/`, `tests/` or the root `conftest.py` is edited: the review's findings are collected, not applied. No pytest runs while a long run of the owner's is live.
3. A change the review asks for is made after the gate exits and committed, and step 2 runs again. A task closes on a clean review and a green gate of its final commit.

The fast gate's recorded target is 16 minutes. The new suites will lengthen it; each stage's exit records the time on a quiet machine.
